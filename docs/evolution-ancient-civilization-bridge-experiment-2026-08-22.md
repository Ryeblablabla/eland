# 古代文明桥接规则实验（2026-08-22）

## 状态与结论

状态：**部分接受**。

铸造场承接后续冶金的因果路径在自然历史中触发并通过配对验收；公共厅堂发起与青铜工具定向教学只通过了直接机制回归，三个 30 年样本均未自然触发，不能宣称已经提高古代文明到达率。当前不增加文明指数奖励或外部影响力因子。

## 可证伪假设

最早断点依次是：

1. 公共厅堂要求一个发起者预先独占全部终材，阻断多人材料汇合；
2. 铸造场落成后，后续冶金仍可能返回更近的陶窑，无法形成稳定铸造实践；
3. 青铜工具单件难以进入交换，制作技术也可能被普通高置信知识挤出教学候选。

若修复成立，在不读取文明阶段或里程碑的前提下，应出现更多公共厅堂合法发起 / 贡献、铸造场真实生产、青铜工具制作 / 使用 / 教学；未触发种子不应发生旁路变化。人口、时代阶段、项目完成与阻塞作为护栏。

因果链仍是：`pressure → perception → memory → need → project → plan → legal action → consequence → learning → transmission → institution`。修改只位于局部观察、项目材料协作、固定工位选择、交换与教学候选，不把观察器指标写回人物目标。

## 最小修改

- 公共厅堂：人物观察到青铜或青铜工具、烧结砖，以及木牍或“木材 + 石制工具”时可以发起；材料不必由发起者预先独占。只有 `civic-coordination` 可复用固定场地材料请求，普通协调项目不扩展。
- 铸造场：可见或记忆后仍可核对的铸造场优先于陶窑成为后续冶金固定工位；实际生产事件记录 `facilityMaterialId`，批量效果仍由领域执行器裁决。
- 工具采用：保留原有“用更高阶备用工具替代低阶待交换工具”路径；额外允许持有者在至少保留石制生产工具时交换单件青铜工具。
- 工具教学：教师可靠掌握青铜工具配方、身边学习者近期完成真实生产劳动且缺少同等工具时，把该技术插入前三个教学候选；普通教学排序不变，来源引用学习者劳动事件。

## 配对方法

最终有效矩阵使用种子 `185 / 20260815 / 20260821`，每个运行 30 年、每月 15 个规划刻度、相同配置。为避免工作区同时存在的其他改动与构建缓存污染比较，先冻结同一源码快照为两个临时源码树，再只在基线副本撤去上述六个文件中的规则修改；`diff -qr` 确认两棵树只有这些文件不同。两组使用独立端口和独立 SQLite。

有效产物：

- 基线矩阵：`three-body/data/experiments/paired-baseline-ancient-bridge-v3-20260822.json`
- 候选矩阵：`three-body/data/experiments/paired-candidate-ancient-bridge-v5-20260822.json`
- 基线事实库：`three-body/data/experiments/paired-baseline-ancient-bridge-v3-20260822-sqlite/eland.sqlite3`
- 候选事实库：`three-body/data/experiments/paired-candidate-ancient-bridge-v5-20260822-sqlite/eland.sqlite3`

早期 `baseline/candidate-ancient-bridge-v1`、`candidate-v2` 与 `paired-*-v2` 因主进程、Worker 或工作区快照不一致而作废；`paired-candidate-v3/v4` 暴露并拒绝了两个过宽实现：把材料请求扩展到所有协调项目，以及覆盖既有低阶工具交换。失败产物保留，不作为效果证据。

种子 `20260815` 的铸造场存量均为 2，候选不是凭空增加设施，而是让已有设施从 2 次真实承接提高到 5 次；青铜从 14 批、5 名生产者提高到 18 批、8 名生产者，并首次完成青铜工具项目、形成 5 次真实使用。两条未触发种子的完整事件历史逐条相同，说明收窄后的规则没有在前青铜阶段扰动选择。

三个样本都没有公共厅堂项目、青铜工具交换报价或青铜工具教学事实。它们的直接回归证明动作链可合法形成，但没有自然历史证据支持到达率结论。下一轮若要验证这两段，应选更长的 50 / 100 年配对或增加能更早产生相关前置压力的通用机制；不能用文明指数奖励、指定人物 / 种子特判或外部影响力直接推过门槛。

## 附带的持久化修复

实验期间发现旧状态根用 V8 序列化字节计算末事件摘要，在新鲜演化 Worker 与长期运行 API 进程间可能不稳定。状态根元数据升级为 schema v2，使用递归键排序的规范 JSON 哈希；旧 schema v1 仍以 chunk SHA-256、lineage 和事件计数兼容读取，下一次保存通过 replace 升级。该修复只影响事实校验，不改变模拟结果。
