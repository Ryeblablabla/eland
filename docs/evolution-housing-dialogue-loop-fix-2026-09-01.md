# 住房重复立项与开放交谈空转修复（2026-09-01）

状态：实现完成；定向因果测试通过，按用户要求未继续运行候选长程矩阵。

## 假设

### H1：住房容量感知

当前人物把“本人此刻没有站在住所内部”与“局部没有可用住所容量”混为同一事实。在存在可见、可达且未占用的真实住所位置时，恶劣天气仍可触发新的 `weather-shelter` 项目；项目完成后，人物换一个室外位置又能用新月份 ID 重开同类项目。

若把当前避护状态、可达空位与容量缺口分开，并让已有空位先产生进入住所行动，那么同样人口和气候下的重复住所项目、未完成碎片结构应下降；当局部确实没有可达空位时，建造仍应出现并完成。

验收：

- 定向状态中存在可见、可达空余住所时，不生成新的普通住所 proposal，仍保留进入住所候选；
- 所有可见住所位置被占用或不可达、且本人确有冷热 / 恶劣天气压力时，仍生成住所项目；
- 三个配对种子的 10 年候选历史中，住所完工次数和未完成结构不再明显超过人口与功能容量需要；不以文明指数变化作为成功标准。

### H2：开放交谈 episode 与语义新鲜度

当前 model-owned `open` affordance 每月生成新的 episode 身份，不读取上一轮完整语义 basis；规则 response 又按预编译的 `acknowledge` 提前关闭 episode，因此 speech 模型返回 `disposition=continue` 也无法保持权威会话。结果是同一人物对在没有新共同事实时不断以“上回没接好 / 最近怎么样”重开。

若最终台词的 `dialogueMove / disposition` 能在发布后更新同一个 ConversationEpisode，且关闭后的新 open 必须携带相对上一轮的新来源，那么连续对话会沿精确父句推进，无新事实的同对寒暄不会按月重开。

验收：

- speech-only 返回 `continue` 时，同一个 episode 保持 `awaiting-response`，下一轮响应引用上一条精确 SpeechLine；`close / rupture` 或达到回合 / 时限后关闭；
- 已关闭的同人物 `open` 在没有新增 grounding source 时不再生成；出现新的本人可追溯共同事实后重新开放；
- 预测台词 prompt 不再提供可被批量照抄的固定“粮和柴”成句；结构化预测事实校验保持不变。

## 基线与矩阵

- 基线：实现补丁前的当前工作区；保留现有未提交修改，不把 `HEAD` 冒充当前行为。
- 模型策略：后台演化关闭模型；真实台词连续性另用定向 speech / episode 测试验证。
- 初步矩阵：种子 `18,185,20260817`，每个 10 年，`repeat=1`。
- 省略：20/30 年与终局审计。本轮属于快速回归修复；若三个 10 年样本方向分歧，再扩展时长，不把初步矩阵描述为完整长期结论。

## 决策规则

- 接受：两个定向因果链均通过，三种子短程没有出现“禁止必要建造”或“关闭全部生活对话”的回归。
- 修订：重复下降但必要建造、回应连续性或新事实重开任一失败。
- 拒绝：仅靠次数上限 / 全局人口知识压低事件，或把模型文本直接变成未经验证的世界事实。

## 实现与验证结果

- 住房：局部容量只统计完整可见且从本人位置可达的住所位置；可见占用位置不再作为可用避护目标。普通住所 proposal 把真实容量短缺与本人即时避护分开：存在可见空位或本人记得且可达的住所时，寒热、烈火与强风暴先提供入住所行动，不再仅因站在室外新建项目。
- 对话：model-owned open 只暴露相对双方仍记得的既往 open 新增的非对话来源；上一轮 opening / response ActionFact 不能自我喂回。提交边界再次验证来源新鲜度。最终台词的 `continue` 在四回合 / 六个月边界内重新打开同一 ConversationEpisode，`close / rupture` 关闭；ActionFact、知识与关系不被文本改写。
- 台词：speech-only 请求新增同一听者相关的至多四条既往精确原话；无精确父句时禁止换词复读。预测示例删除固定“粮和柴”句，并禁止在没有当前来源时附加统一准备口号。
- 通过：`test-local-shelter-capacity.mjs`、`test-grounded-conversation.mjs`、`test-agent-memory-store.mjs`、`test-live-speech.mjs`、`test-model-decision-context.mjs`、`test-agent-cognition.mjs`。
- 通过：`npm run backend:build`。
- 文档：`knowledge-base/rules-page.js` 已同步规则导览；运行 `knowledge-base/npm run sync:docs` 更新核心文档镜像。

基线运行 `baseline-housing-dialogue-loop-20260901-v1-s18-y10`、`-s185-y10`、`-s20260817-y10` 均到达 120 月。初次矩阵 CLI 有两项等待请求超时，但后台运行随后正常完成，状态保存在 `three-body/data/experiments/baseline-housing-dialogue-loop-20260901-v1-status.json`。用户要求实现完成即结束，因此没有继续创建候选长程运行；本轮结论限于机制级定向验证，不声称已有长期分布结论。

## 2026-09-02：伴生未完成结构修复

截图与实时状态显示每个标准住所被投影为一组两构件未完成墙体和一组单构件完成屋顶。最早断点在物理结构连通：建造蓝图为可通行内部留下空间，使墙顶与屋顶只沿边斜接，而索引只接受六方向面接触；完成判定又允许屋顶读取相邻墙体，于是同一住所被拆成两组。

候选只为共同形成同一个已验证 `shelterGeometry` 的建造屋顶与侧墙添加功能连接，不开放通用斜向连通。定向测试证明标准下墙、上墙、屋顶三构件只形成一个完成结构；没有共同住所几何的普通斜邻构件仍形成两个结构。该机制不改变建材消耗、住所完成条件、容量或人物项目选择。
