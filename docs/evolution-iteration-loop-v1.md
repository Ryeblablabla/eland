# ELAND 文明演化双闭环与实验协议 v1

状态：当前权威的文明演化迭代方法。本文规定游戏内部如何形成自演化，以及开发时如何通过多时长、多种子、多次运行判断一个规则修改是否成立。

关联：[规则优先人物架构](./rule-first-agent-architecture-v1.md) · [文明指数](./civilization-index-v1.md) · [纪元、预言与生态](./three-body-era-ecology-v1.md) · [涌现能力底座](./emergent-capability-substrate-v1.md) · [首轮持续项目实验](./evolution-project-loop-experiment-2026-08-15.md)

## 1. 核心原则

ELAND 不以预设科技树或文明任务清单驱动人物。复杂文明必须从世界压力、人物经验、持续项目、多人协作和知识传承中形成。

- 世界事实产生动态需要，不赋予“提升文明”的抽象欲望；
- 项目是持续演化单位，原子动作只是项目步骤；
- 规则裁决物理合法性和客观后果，文化偏好由经验和传播形成；
- 重复有效的个人行为形成技术或实践；
- 重复有效的多人协作形成角色、规范或制度；
- 文明指数、阶段和里程碑只观察结果，不进入人物评分；
- 阶段门槛同时服务游戏性：优先选择玩家可见、可操作、可回放的小型真实闭环，不用历史上的工业人口或产量规模故意压低达成率；
- 模型可以提出假说、表达、协商和创意，但不能替代本地计划、动作和裁决。

## 2. 游戏内部的自演化闭环

```text
世界压力
→ 局部感知
→ 有来源记忆
→ 动态需要
→ 跨月项目
→ 前置条件与子任务
→ 原子行动
→ 物质、身体和社会后果
→ 修正知识、信任和效用
→ 教学、实践、角色、规范或制度
→ 新的世界状态与压力
```

任何复杂能力都应能沿这条链回溯。若链条中断，人物可以合理地不产生该能力；观察器不得把缺失直接判为规则漏洞。

### 2.1 动态需要

人物的长期动机来自事实：

| 动机 | 来源 | 典型项目 | 可能涌现 |
|---|---|---|---|
| 风险预备 | 可信预言、气候伤害、野兽 | 住所、衣物、武器、避难 | 预言者、建造者、守卫 |
| 储备缓冲 | 预计短缺、孩子、长乱纪元 | 储粮、保鲜、容器、配给 | 仓储角色、分配规则 |
| 能力投资 | 重复失败、受伤、高劳动成本 | 工具、交通、药物 | 工匠、学徒、专业化 |
| 完工与承诺 | 未完成高价值项目、已有承诺 | 继续、取材、招募 | 多人项目、贡献声誉 |
| 照料与传承 | 伤病、儿童、专家衰老或死亡 | 照护、教学、记录 | 照料者、口述史、记录 |
| 针对性探索 | 重要项目被未知问题阻塞 | 观察、受约束实验 | 与现实问题相连的发现 |
| 急性求生搜索 | 缺水且没有可见或记忆水源 | 沿可见、可通行的低重复方向搜索 | 水源记忆、迁徙路线；不得读取隐藏水格 |

人物不直接知道隐藏配方。已知技术可从目标反向展开材料链，但精确 BOM 必须能追溯到本人仍可靠的技术 / 规则 / 记录，或本人真实完成的配方事实；仅有 activeProject 或 desiredFunction 不构成知识。无 provenance 的未知技术只能依据可感知性质、失败记忆和当前问题提出试验。未知材料问题只能表达功能角色、相态、外形、表面观感，以及拿取 / 核验后获得的粗负重和刚性，不能携带正确 material ID、rule ID 或预期产物，也不能用项目目标材料做隐藏加分。试验按个人或传播来的 response / no-response 证据更新，并受候选、尝试和关闭预算约束。

人物在廉价因果 BDI 之后可以比较少量本人能够命名的后果，但这不是世界预测器：一次人物决策最多看 4 个根候选、每节点 2 个后继、深度 3、总计 24 节点。选择与执行审计复用同一棵树；required / commitment 与 follow-up 只做廉价排序，不另开前向预算。只有 response 与 no-response 会改变下一步选择时，信息才有价值；没有替代项、没有真实两难或观察后仍选同一步时，VoI 必须为 0。前向比较不能创造候选、绕过合法性、职责或急性生存优先级。

### 2.2 项目

项目至少保存：

```text
触发事实、功能目标、所有者与受益者、地点或对象、
已知方案、缺失前置、预留资源、参与者与承诺、
截止或复核时间、进度、失败和状态。
```

建造项目应追求遮蔽、容量、入口、保温或储藏等功能，不追求固定预制外形。生产项目应能从有用结果反向展开中间产品和取材步骤。多人项目必须记录真实贡献，贡献才可影响信任、情境化合作后验、角色和制度；一次接受或一次完成不能自动沉淀为稳定制度。

社会学习按“目标人物 × 合作情境”分别记录回应、接受意愿和履约可靠性，不能用一个总声誉替代。拒绝只证明当次不愿意，没有回应只影响回应预期；只有真实履约 / 违约、带贡献证据的共同项目完成，以及授权贡献到分配闭环，才影响可靠性。至少跨两个不同月份的可靠成功才支持 person-local coordination practice，新的可靠性反证应把它标为 contested。practice 只能开放共同体或治理提议，仍须经过真实需要、物质事实和参与者接受，不能直接授予规则或权力。

项目能力判断必须区分“看见”“当前可合法取得”和“已经放置并能发挥功能”。旁人背包里的工具或设施只是观察证据；便携能力要求本人持有或眼前有可取得的真实掉落物，设施能力要求世界中真实放置的设施，记忆地点还要重新核对当前体素。观察证据可以触发学习或压力，但不能直接满足能力缺口。

局部等价项目应优先复用：候选阶段检查功能、受益者、目标知识与场地重叠，提交时再按当前权威状态重验。同刻度竞争创建时，后提交者合并受益者与触发事实、把意图重绑到既有项目；非所有者只在创建当月有界等待，远方且不重叠的工作仍可并行。材料协作则必须由追加式请求和精确请求引用形成，状态从请求期限、当前缺口、收件人可用性与真实转移事实派生，转移量不得超过请求余量或实时缺口。当前实现范围只覆盖固定场地的合金项目；不能把这项窄机制描述成所有项目都已具备通用招募物流。

## 3. 开发迭代的证据闭环

```text
提出可证伪的能力假设
→ 保存不可变基线实验矩阵
→ 检查代表性历史的因果链
→ 找到最早断点
→ 修改最低层通用机制
→ 用相同矩阵运行候选版本
→ 比较分布、发生率和历史
→ 接受、修订或拒绝
→ 更新权威文档与新基线
```

单次运行只能提供案例和候选问题，不能单独支持 A/B 结论。一次运行中没有出生、技术或制度，可能是合法历史；只有确认存在适用压力和完整前置，却被引擎缺陷阻断，才能称为规则漏洞。

## 4. 实验矩阵

### 4.1 时长

| 时长 | 主要观察 |
|---|---|
| 10 年 | 行动流、早期生存、生产链、建造、首次学习和信任 |
| 20 年 | 繁衍后果、重复项目、技术扩散、生态、早期分工 |
| 30 年 | 延迟人口效应、知识损失、角色稳定、规范、制度和多纪元韧性 |
| 50/100 年 | 跨代连续性、稀有事件、成熟制度和长期稳定；短期证据通过后再使用 |
| 至文明终止或 1000 年 | 只用于关键候选和最终文明上限审计；当前运行时只在全员死亡或 endpoint 到达时终止，休眠与恢复中的存活者不会被当作文明灭绝；不得超过 12000 月 |

跨层规则修改至少选择两个适用时长；只影响早期动作的窄修改可先用多个 10 年样本，再按因果时标扩展。100 年和 1000 年都不是每次迭代的固定成本。

没有“文明必须在 30 年内到达现代”的验收条件。短程矩阵用来验证动机、合法动作和局部闭环是否工作；若前置在真实历史中需要更长时间，应在短程证据通过后扩展到 50/100 年或有界上限审计，不为赶期限向人物注入阶段目标。

### 4.2 种子与重复

- 普通规则修改至少使用 3 个种子；高方差或稀有事件增加样本；
- 基线与候选必须使用相同种子、时长、初始配置和模型策略；
- 每个种子对控制初始条件，但结论来自完整配对集合，不来自单个种子；
- 本地规则完全确定时，同种子重复运行只验证可回放性，不是独立统计样本；
- 只有模型调用、玩家输入、并发或其他非确定性存在时，才把同种子多次重复纳入分布，并分开报告种子内与种子间方差；
- 灭绝、停滞、无出生和失败项目必须保留在样本中，不得静默换种子；
- 不得在看到结果后缩短、延长或替换矩阵而不声明原因。

建议的自适应层级：

1. 快速诊断：至少 `3 seeds × 10 years`；
2. 跨期验证：对适用机制使用 `3–5 seeds × 10/20/30 years`；
3. 里程碑验证：在前两层稳定后增加种子或 50/100 年跨代运行；最终上限审计可继续到文明终止，未终止时最多 1000 年。

## 5. 因果诊断顺序

按顺序检查最早断点：

1. 压力或机会是否真实存在；
2. 人物是否能感知；
3. 是否形成带来源记忆或知识；
4. 是否产生动态需要；
5. 是否建立持续项目；
6. 是否能展开前置和预留资源；
7. 是否存在合法且有效的动作；
8. 后果是否改变未来选择；
9. 是否能传播、协作并沉淀为稳定结构。

问题分类为：合法结果、缺少压力、感知缺失、记忆缺失、动机缺失、项目规划失败、可供性或效果缺失、协调失败、观察器错误、引擎缺陷。

只修复最早断点。因果机制完整以后才调整数值权重；不得用人物、种子或目标结果专属规则掩盖断点。

诊断失败重试时，必须比较结构化 intent basis，而不是 option ID 或自由文本摘要。动作、目标、数量、人物、项目、记录、关系或来源发生真实变化，都是重开证据；完全相同且无新来源的失败 basis 才可在有限窗口内冷却。当前规则冷却失败当月起 0–6 个月，第 7 月恢复，必须回应与履约绕过；不能解析结构 basis 的旧自由文本记忆按 fail-open 处理。

移动本身也要检查因果质量。追逐另一个同时移动的人、材料点与工地之间来回摆动、或每个规划刻度重选相邻格，都属于计划编译/协调缺陷，不应被“探索度提高”掩盖。自愿教学和普通社交应优先发生在自然同地机会；只有履约、照料、共同项目或明确会合约定才足以支持跨地移动。结伴与共同体身份不能自动扩张成对成员实时坐标的无界追踪；共同生活应围绕稳定地点或真实住所累计，具体互动再单独产生有目的的会合。

社会重试也必须有新因果，但不使用“过去两个月说过就删除候选”这类固定冷却。可选社交发起仍进入候选集，`social-repetition` 因果树再从人物自己的沟通记忆比较“同一受众 + 同一语义主题”的最近发起与当前事实 basis：没有新增 `sourceFactIds` 时降低预期价值，上次未回应、拒绝、保留或违约时降权更重。本人可追溯的新事实会重新打开话题；即使没有新事实，与求助、照护或困境主题直接相关的水分、营养、健康或急性状态显著恶化，也可使再次开口变得值得。这个机制不是次数上限，遗忘也会自然改变人物能否作出比较。

社会重复成本只负责软排序，不削弱协议状态机。协议 ID 幂等、每位必需回应者只能回应一次、同一生活对话事实 basis 只能开场一次、同一开场只能回应一次，仍由领域层硬验证；换临时 ID 但复用同一组事实来源不算新证据，必须回应和履约也不进入重复成本。诊断“社交压过生产”时，要分开统计真实沟通动作、持续意图的领域标签，以及该意图编译出的移动、取材和生产动作，不能把三者混成聊天量。

可选社会注意力也要同时保留利用与探索：同一 typed cooperation context 超过两名对象时，人物保留本人后验最高的两名，并稳定轮换一名其余对象；required response、履约 / 撤回和生殖不受这项预算削减。诊断时应验证分组来自 typed semantics，而不是 option ID 前缀，并检查低后验对象是否仍能按月份获得探索机会。

## 6. 观察指标

每个实验同时检查聚合数据和历史证据：

- 流畅性：死锁、空闲、重复重试、移动占比；
- 项目：提出、启动、完成、放弃、预留和参与人数；
- 生产：链深、转化率、物品采用、闲置材料；
- 建造：功能容量、完工率、重复工地；
- 社会：完成合作、回应 / 意愿 / 可靠性分维后验、supported / contested practice、稳定角色、治理和冲突处理；
- 知识：发现、验证、教学、记录、失传和跨代保留；
- 韧性：面对纪元、天气、生态、疾病和短缺的适应；
- 观察器：证据、封顶、阶段门槛和指标投机；
- 模型独立：规则决策、模型决策、Token 和离线可完成性。

物流至少同时报告容器制作、仍在场的容器、实际存取次数和终局储量；社交至少同时报告实际沟通、提议/回应、重复提议和意图标签。只有“制作了容器”或“拥有社交意图”都不能证明对应功能已经工作。

连续指标报告中位数、范围及必要的分位数；离散能力报告发生率。配对报告每个种子的候选减基线差异，并单列与总体方向相反的种子。至少保留一条成功历史和一条失败或分歧历史。

## 7. 接受标准

只有同时满足以下条件才接受修改：

- 目标因果能力在实验矩阵中改善，或明确说明只在什么条件下出现；
- 人物行为能够从局部事实解释；
- 面向玩家的阶段成就有可见、可操作、可追溯的世界证据，难度与当前游戏规模相称；
- 没有依赖换种子、强制结果、文明指数奖励或同步模型调用；
- 流畅性、生存、人口和其他关键能力没有未接受的明显退化；
- 代表性历史显示问题确实被解决，而非只增加事件数量。

机制只在狭窄条件工作并暴露下一断点时继续修订；指标变好但历史机械化、被强制或产生更大回归时拒绝或回滚。

允许把一个有独立因果证据的窄机制判为“接受”，同时把包含它的整体候选判为“继续修订”。例如容器确实被放置和使用，证明可供性修复成立；若同一候选的 30 年死亡或人口退化，则不得据此升级整体基线。报告必须明确区分机制级决定与候选包决定。

## 8. 每轮交付

每轮迭代保存并报告：

```text
假设与预期因果链
基线代码版本、配置和矩阵
候选代码版本、配置和矩阵
各时长聚合结果
配对种子结果
代表性成功与失败历史
回归与不确定性
接受 / 修订 / 拒绝决定
下一项可证伪瓶颈
SQLite run ID、实验矩阵与离线摘要路径
```

后端实验矩阵可使用个人技能 `iterate-emergent-civilization` 附带的 `scripts/run_matrix.mjs`。权威运行写入 `three-body/data/eland.sqlite3`，基线与候选必须使用唯一 run ID，不得覆盖。长程 runner 使用绝对 `requestedEndMonth` 与完整 expected identity（label、seed、文明号、气候配置、endpoint、起始月）重复提交 ensure-through：仍在运行的同一任务是幂等确认；服务重启后，持久化为 `running` 但已失去内存 job 的任务会从当前权威月份继续；已到终点但报告未落盘的任务只补报告，不重复推进。身份或 horizon 不匹配必须失败，不能把同前缀旧运行静默当作新候选。矩阵脚本导出的 JSON 只用于离线交换、聚合和复核，不是运行时状态，也不能回写模拟事实。历史报告中的 `three-body/data/runs/` 路径仅表示迁移前的实验产物位置，不代表当前存储协议。

本协议的首轮完整应用见[持续项目与因果动机实验（2026-08-15）](./evolution-project-loop-experiment-2026-08-15.md)：结论来自 3 个配对种子和 10/20/30 年共 9 对运行，并明确保留了物流、阻塞恢复和制度形成的未解决问题。
