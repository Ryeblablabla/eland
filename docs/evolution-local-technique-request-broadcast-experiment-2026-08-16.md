# v29 同地技术请求广播实验

状态：请求广播合法性通过，整体候选拒绝。

## 决定

3×10 年请求为 `5 / 4 / 0`，重投影后的唯一 project/teacher 为 `9 / 4 / 0`，重复与因果来源守卫为 0，但示范仍为 0。生产项目完成 `0 / 1 / 4`，中位数 1，低于 v28 门槛 2。旧审计器曾把多受众请求误报为 person mismatch；按“每个实际到达 project/teacher 对”修正并重投影后为 0。请求历史中实际到达的受众在请求当月都没有匹配可靠技术。

此外，v29 把整个 audience 集合编码进 representation/option ID；这会改变确定性规划器的稳定排序键，使与广播因果无关的行动历史大范围分叉。保留“真实 reached teacherIds 可含多名同地受众”的机制，拒绝整体候选。下一轮先恢复与 v28 相同的稳定主受众 ID，再检验广播本身。

## v28 后的最早断点

v28 的 3×10 年中请求为 `2 / 1 / 21`，但示范为 0。历史审计显示，请求编译器只选择按 ID 排序的第一个近身者；多个请求发生时世界中已有匹配功能的可靠技术持有人，但实际受众都不是持有人。项目已经产生真实需要，请求也已执行，最早断点是请求没有覆盖当下同地群体。

## 单一因果假设

若学习者把同一个项目困境一次性告知所有当下同地、尚未被该项目询问过的人，而不是任意挑选一个人，那么任何实际收到请求、拥有匹配可靠技术且能以当前实体执行的人都可现场示范。广播只使用可见同地人物，不读取他人知识、不跨地追踪、不赠送材料，也不保证有人会。

冻结链条：

```text
active inquiry
→ 本人可见且同地的未询问受众集合
→ 一次 project-bound request action
→ reached teacherIds 保存真实到达者
→ 其中可靠持有人以本人实体执行
→ v28 demonstration → imitation → reliable 链继续
```

## 守卫与矩阵

- 同一项目/受众对最多一次请求；受众不在同地不得进入 `teacherIds`。
- 演示者必须在请求实际到达列表中；仍需匹配 function、可靠知识、同地、真实输入、合法 target 和真实 response。
- 广播不得恢复 hypothesis 预算、不得读取文明指数、不得创建跨地会合或直接复制技术。
- 定向测试加入“ID 更靠前但无知识的旁观者 + 可靠示范者”，二者都收到一次请求，只有可靠者能示范。
- 自然候选使用 seeds `185 / 20260815 / 20260816`、chaos `0` 的 `3×10y`，直接基线为 v28 quick；只有全部守卫为 0、至少 2 个种子有请求且至少 1 个种子有真实示范，才扩展 `3×30y`。
- 生产项目完成中位数不得低于 v28 的 2；若示范仍为 0，判定下一断点而不调权重。
