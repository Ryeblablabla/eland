# 生产工具持续升级实验（2026-08-19）

## 基线审计

基线采用已通过配对护栏的 v16。三个 30 年样本都停留在原始部落；共同的农耕定居门槛之一是 `material:masonry-stone:distributed`。这不是文明指数不足：三个样本分别已经产生大量石工相关设施或批次，但石制工具投入实际生产仅为 `3 / 8 / 0` 次，低于分布式能力所需的真实采用证据。

事件历史表明，工具执行链本身可工作：人物持有石制工具并执行采木或收获时，动作会携带工具并获得更高产量。最早断点位于项目形成之前：生产效率压力只记录 `production-tool-present / absent`。木制生产工具一出现，压力固定减少 `28`，项目候选又要求 `!hasProductionTool`；因此最早的木制工具被当作永久充分解，不会因为人口、食物不足、受抚养者负担或实际效能有限而再次形成升级项目。

30 年事实与该断点一致：

- seed `185` 只有第 `3 / 35` 月两个生产效率项目，均停在木制工具；后来虽偶然制造 `8` 件石制工具和 `1` 件石锄，石制工具仅完成 `3` 次生产使用；
- seed `20260815` 只有第 `6 / 45 / 58` 月三个生产效率项目，均停在木制工具；石制工具使用 `8` 次；
- seed `20260816` 只有第 `8 / 10` 月两个生产效率项目，均停在木制工具；此后 350 个月内没有石制工具产出或使用。

外部天气与死亡会削弱持有者连续性，但无法解释三个种子都在木制工具出现后停止提出升级项目。主断点是内部的二元充分性判断。

## v17 工具效能阶梯候选（预登记）

### 可证伪假设

若生产压力按人物眼前可辨认的工具效能获得分级缓解，而不是被任意一件工具永久清零；且每个新项目必须产生比项目形成时已观察到的最好工具更有效的实体结果，那么持续的人口和食物压力应能自然形成第二轮工具改进。改进仍须经过真实材料、个人知识、假说尝试、动作结果和后续使用，不能由文明阶段或年份直接授予。

### 候选边界

- 只把现有生产工具按执行器已经体现的产量效能分级：无工具、木/骨工具、石制工具/石锄、青铜工具、铁制工具。压力缓解随效能增加；木制工具只能部分缓解，不能在仍有明显拥挤、饥饿或食物不足时关闭需要。
- 发展压力的局部人口和食物计算必须包含观察者本人；规划调用传入的 `visiblePeople` 只有他人，而默认压力视图原本包含本人，两条入口不一致。候选在发展压力内部去重合并本人和眼前他人，不引入远处人口。
- 生产效率项目保存形成时本人可观察到的最佳工具层级；项目只有得到更高效的真实工具才算完成，已有木制工具不能让新项目瞬间完成，也不能反复复制同级工具冒充进步。
- 第二轮项目仍使用 `efficient-production` 这一功能目标，通过眼前材料、可靠知识或有限的有来源假说寻找石制工具与石锄链；不读取 `civilizationIndex`、时代门槛、全局能力观察器或未来配方。
- 不改变食物产量、人体消耗、天气、生育、死亡、文明指数公式、石工能力观察阈值或时代门槛；不添加种子、人物、运行 ID 或年份特判。

### 配对矩阵与接受标准

- 基线：`candidate-private-food-floor-v16`；候选使用 seeds `185 / 20260815 / 20260816`、`10 / 20 / 30` 年、`chaosIntensity=0`、`climateBias=balanced`、每月 15 个行动刻度和纯本地规则。
- 发生率：至少两个 30 年种子在已有木制工具后形成新的生产效率项目；这些项目不得以同级木制工具立即完成。
- 因果结果：至少两个种子的石制工具或石锄真实生产使用次数高于 v16，且至少一个种子形成可回放的“压力变化 → 升级项目 → 材料/知识步骤 → 更高效工具 → 生产使用”完整链。
- 生存护栏：30 年不得出现新灭绝、幼童死亡或幼童冷热暴露死亡；人口中位数不得低于 `4`，出生中位数不得低于 `2`。
- 行为护栏：30 年移动占比中位数不得高于 v16 的 `46.38% + 5` 个百分点；生产项目完成中位数不得低于 `4`，功能制度中位数不得低于 `2`。
- 文明阶段或指数上升只作观察结果。若升级项目普遍长时间锁住人物、只增加无使用的工具库存、只在一个种子发生，或靠放松观察器门槛才过关，则拒绝候选并保留失败样本。

## v17 结果：拒绝捆绑候选，工具阶梯尚未得到干净验证

v17 违反了生存与行为护栏：30 年人口中位数由 v16 的 `4` 降至 `1`；seed `20260815` 在第 `174` 月灭绝，并出现 `1` 次幼童死亡与 `1` 次幼童冷热暴露死亡；seed `20260816` 只剩 `1` 人并出现 `1` 次幼童死亡。移动占比配对变化的中位数增加 `9.87` 个百分点，也超过护栏。

工具升级项目确实在两个种子形成，但都没有完成：seed `20260815` 第 `86 / 117` 月的两个 tier-1 项目分别在第 `110 / 141` 月受阻；seed `20260816` 第 `56` 月的 tier-1 项目在第 `80` 月受阻。30 年石器真实采用动作由 v16 的 `3 / 8 / 0` 变为 `8 / 0 / 2`，只有两个种子提高且没有一条“升级项目完成 → 改进工具 → 生产采用”的完整链。

更关键的是，第一行为分岔早于升级机制。seed `20260815` 第 `1` 月，v16 的 Armstrong 沿原意图前往聚集点；v17 因“发展压力补计本人”同时改变了所有发展项目压力，改为取石、远行取黏土、制窑并设置窑炉。它不是工具层级产生的局部差异，而是扩大了高温、储备、水利等整套发展项目的触发范围，导致后续历史不可用于单独判断工具假设。

决定：拒绝 v17 整版；撤回“压力视图补计本人”，保留失败样本。矩阵：`three-body/data/experiments/candidate-production-tool-upgrade-v17.json`；配对差异：`three-body/data/experiments/compare-v16-v17-production-tool-upgrade.txt`。

## v18 工具阶梯隔离候选（预登记）

- 以 v16 为行为基线，只保留工具效能分级、木制工具后的升级项目，以及项目形成时的工具层级快照；恢复 v16 原有发展压力人口视图。
- 无工具时压力数值和项目材料条件必须与 v16 一致；候选历史若在任何工具出现前分岔，先按实现错误处理，不把结果归因于升级机制。
- tier-1 升级项目不得被已有木制工具完成；仍须通过真实石与木形成石制工具，再通过石制工具与木板形成石锄，或依靠人物自己已有的可靠经验复现。
- 使用与 v17 相同的三种子 `10 / 20 / 30` 年矩阵和接受标准；另外要求升级项目动作不应在 24 个月复核期内主要由远程搜索构成。若两个以上升级项目都受阻且没有完整采用链，即使偶然石器数量增加也拒绝。

## v18 结果：采用增加，但项目完成语义自相矛盾，拒绝

v18 隔离掉了 v17 的人口视图改动，第一行为分岔均发生在人物已经观察到石制工具之后，因而工具阶梯是实际差异来源。30 年石制工具或石锄的真实生产使用由 v16 的 `3 / 8 / 0` 增至 `7 / 9 / 7`，三个种子都增加；但这仍不是可接受的完整因果链。

三个种子的升级项目结果为：

- seed `185` 第 `170` 月形成 tier-1 升级项目，第 `194` 月受阻；
- seed `20260815` 已在早期观察到 tier-2 石制工具，因此没有形成重复升级项目；
- seed `20260816` 第 `54` 月形成 tier-1 升级项目，人物取得石与木并成功制造、验证石制工具，却在第 `78` 月受阻。

seed `20260816` 暴露了确定性的实现断点：生产压力把 `StoneTool` 判为 tier 2，项目候选也以 tier 2 判断升级已经必要且可行，但项目完成物清单只有 `StoneHoe / WoodTool`。因此同一个石制工具一方面被当作高效工具，另一方面又不能完成“高效生产”项目；人物随后尝试无效的 `StoneTool + WoodTool`，最终因无候选动作而受阻。

生存护栏同时失败。30 年人口为 `5 / 2 / 3`，中位数由 v16 的 `4` 降至 `3`；seed `185` 新增一名幼童在第 `272` 月因连续高温暴露死亡。生产项目完成数为 `9 / 10 / 4`，功能制度为 `4 / 3 / 1`，制度中位数满足护栏但 seed `20260816` 低于基线。移动占比中位数及配对变化也未通过预登记限制。不能用石器采用增加抵消这些回归。

决定：拒绝 v18；保留失败样本。矩阵：`three-body/data/experiments/candidate-production-tool-tier-v18.json`；配对差异：`three-body/data/experiments/compare-v16-v18-production-tool-tier.txt`。

## v19 升级完成语义修正（预登记）

### 可证伪假设

若 tier-1 升级项目把自己实际制造出的 tier-2 `StoneTool` 识别为完成结果，项目应在获得改进工具时结束，而不会继续占用人物、尝试无效组合并因停滞受阻。若仅修正这处不一致仍不能形成“升级完成 → 真实使用”的链，或仍违反生存护栏，则说明 v18 的问题不只在完成判定，候选仍应拒绝。

### 候选边界与接受标准

- 只修改 `efficient-production` 的完成物语义：baseline tier 1 可以由 `StoneTool` 或 `StoneHoe` 完成；两者都必须严格高于项目形成时的 tier。
- baseline tier 0 继续只由原有的 `WoodTool / StoneHoe` 完成，避免改变第一轮生产项目和任何工具出现前的历史。
- 不修改压力、候选形成、假说顺序、产量、食物、天气、生育、死亡、观察器或文明指数。
- 先用定向测试证明旧项目不被同级木工具完成、石制工具可完成 tier-1 项目；再运行相同的三种子 `10 / 20 / 30` 年配对矩阵。
- 沿用 v18 的全部发生率、完整链、生存和行为护栏。特别要求 seed `20260816` 的第 `54` 月同类项目不再因已得到石制工具而受阻；如果历史时间略有漂移，则用项目的基线层级、产出与终止证据匹配，而不硬编码月份。

## v19 结果：局部因果链成立，整条工具阶梯候选仍拒绝

完成语义修正确实命中 v18 的直接断点：

- seed `185` 的 tier-1 项目在第 `170` 月形成，第 `171` 月制造石制工具后完成；
- seed `20260816` 的 tier-1 项目在第 `54` 月形成，并在同月取得石、制造石制工具后完成，不再于第 `78` 月受阻；
- 三个 30 年样本的石制工具或石锄真实生产使用为 `14 / 9 / 7`，均高于 v16 的 `3 / 8 / 0`。至少两个样本形成了可回放的“局部压力 → tier-1 项目 → 材料与假说 → 石制工具 → 项目完成 → 后续生产使用”链。

但预登记的安全与行为护栏再次失败，而且比 v18 更差：

- 30 年人口为 `4 / 2 / 1`，中位数 `2`，低于 v16 的 `4`；出生为 `6 / 2 / 1`，中位数虽为 `2`，但 seed `20260816` 只产生一名后代；
- seed `185` 出现 `2` 次幼童高温暴露死亡；三个样本均未灭绝，但代际承接已经明显恶化；
- 移动占比为 `51.88% / 56.67% / 31.82%`，中位数 `51.88%`，超出 v16 中位数加 5 个百分点的限制；
- 生产项目完成数为 `13 / 10 / 7`，但功能制度为 `4 / 3 / 1`，制度中位数满足最低线，seed `20260816` 仍退化。

这说明完成判定错误是真实 bug，却不是工具升级方案的全部问题。tier 机制通过额外项目和随后的历史分岔提高了石器使用，同时改变了迁移、照护、生产与生育机会；“更多石器”没有转化成更稳健的共同体。不能因局部链成立就接受整条候选。

决定：拒绝 v17-v19 的生产工具阶梯候选并回到 v16；保留失败样本，不下调文明观察门槛。矩阵：`three-body/data/experiments/candidate-production-tool-completion-v19.json`；配对差异：`three-body/data/experiments/compare-v16-v19-production-tool-completion.txt`。下一轮先审计 v16 的代际承接与长期生存断点，再选择不额外抢占生存、照护时段的最低层机制。
