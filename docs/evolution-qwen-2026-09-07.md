## 首个月基线

`three-body/data/experiments/qwen-resume-baseline-seed31-20260907/` 从初始状态实际运行一个月，未接旧模型历史：3 人存活，3 次 Mind、5 次续编、29 次提供者请求，6 个完成动作、3 个推进、2 个受阻；两次翻译失败，没有造物或后代。

行为证据：人物自主选择探索材料与环境。但柳如是观察食物的步骤却以 `sheltered` 为完成条件；精卫观察木材也出现相同错配。尼尔尝试用黏土包裹食物，世界解释主要产生原样消耗再放回，未证明新功能。这个样本证明 Qwen 链路确实可运行，不证明智能、设施或社会达到目标。

## 针对根因的修复

- 原决策层默认只给 12 秒，即使端点设为 60 秒仍被截短；现默认遵循端点超时，显式覆盖保留。Ollama 单机按人物串行处理，每个人仍保留完整 Mind→Plan→World 链，未改变行为权重。
- 原 Ollama native-json 仅传 format 约束而不在 prompt 中展示 schema，缺少字段含义。现在同时传送格式约束与明确 schema。这与 [Ollama 官方结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs) 的建议一致；仍需真实样本验证语义错配是否减少。
- 另一条既有 r3 根因是拆除脚下木板后缺少身体支撑结算。位置、伤害及后续寻路修复由定向实际执行验证，不通过瞬移或恢复生命值制造成功。

本轮依旧先短程排错，未将一次运行结束或机制测试通过视为完整 Goal 完成。


## 带字段说明与支撑修复的短程样本

`qwen-schema-support-seed31-20260907` 从初始状态完成一个月。逐次日志记录 11 次 HTTP 请求，全部为 `lan-qwen` / `qwen3.5:4b`，无 DeepSeek 请求；响应均正常结束，未被长度截断。但只有精卫的一份 Mind 编译成实际动作，随后完成靠近石堆和观察。三份翻译失败都指向计划入口冲突，不能把服务可用当成行为质量已达标。

原始响应显示 Plan 同时填写 firstStepHandle、experiment、worldAction 和 continuationHandle。现有 JSON Schema 允许这种形状，而本地执行器要求唯一当前入口；提示词的例子也同时列出多个可选入口。因此加入字段说明本身并未解决可执行性，下一次修复必须先对齐格式合同，保留所有方式，但每次只明确选择一个。

支撑结算定向验证已通过：人物与旁人撤板后落地、下一步可走；第一处真实地板、坠落损伤与死亡、融冰附近避让及墙体阻碍、木架坍塌的同月来源事实均覆盖。该验证不替代新模型创造设施的实际历史。


## 唯一行动入口后的三个月样本

`qwen-exclusive-plan-seed31-20260907` 从初始状态运行至第 3 月。实际响应现在每份 act 只携带一个执行入口，批量 Schema 的引用也保持各人物自己的作用域；第 2、3 月无翻译失败。人物有实际移动、采集和交流，仍无造物、协议或后代。

语义问题仍然存在：同月 Plan 续编里，人物想继续询问伙伴，却选择 `o1`（其实际动作是观察或取材）。这类选择虽然格式合法，也不能算人物理解了执行结果。正进行一个已保存失败 Plan 请求的 Qwen 推理模式对照，仅改变 think 与允许输出长度；不注入文明目标，不更换提供者。对照是协议诊断，不会插入任何文明历史。

## 同月听闻与自主保留安排

继续审计三月样本时纠正了两个判断：3 次 talk 都被另外 2 人实际接收，语言并未丢失；17 次 attend 按“人物 + 精确对象”分组没有重复，实际是 Plan 一直说要交谈，却选到依次出现的不同物质观察入口。因此不能通过把不同物质强行去重来修复。

确定的调度断点是每人每月最多两次 Mind 的硬上限，以及旧 Plan 续编优先占用人物、排除刚收到的对话事件。现改为将新 decoded 语言作为人物重新考虑的输入，以原语言波 sourceEventId 去重，Decision 与后续 talk 引用同一波时只处理一次。听闻不代表理解、回应或同意。来源写入 DecisionFact 和 Mind/current；Plan 续编另显示真实操作、对象、局部动作成果与整体目标核验，避免混淆。

`qwen-reception-seed31-20260907` 已从初始状态完成两个月。44+44 次新 Mind、180 次提供者请求，出现 assist、collective、companion 各一份提议，但都仍为 proposed，未形成共同承诺，也无造物或出生。新机会恢复了交谈输入，却暴露每次 Mind 必须生成非空 utterance 的另一约束：一个人说话后旁人又必须说话，形成大量相互触发。不能把高发言次数宣传成丰富社会。

后续新增独立控制输出 `{attention:"keep-current"}`。由模型决定本次输入不改变已选安排，无新语言、无新目标、无隐藏思想文本，也不取消当前动作，且不再调用 Plan/World。计数将“形成新意图”和“保留当前安排”分开。Schema 与真实 gateway 边界定向验证该选择只需一次调用；完整月度调度验证新听闻可超过两次上限、同一语言来源不会反复触发，并允许人物不回应且不产生协议。

候选样本 `qwen-attention-seed31-20260907` 使用新版本从初始状态运行，仍只固定 `lan-qwen`。其社会表现需要读取实际结果后判断。


## 保留安排入口与提议上下文的后续结果

`qwen-attention-seed31-20260907` 完成两个月，第一月 38 次新 Mind、1 次 Plan 续编，第二月 5 次新 Mind、7 次续编并有 6 次翻译失败；模型没有选择 keep-current。没有造物、协议或出生。新增选择在代码和协议上成立，但该样本不支持“Qwen 已能合理保持沉默”的行为结论。

对前一个 reception 样本进一步查因：精卫确实能看到接受/拒绝的引用，但 Mind 的 speechReferences 原来只有类型、状态、日期、等待人数，没有提议者与具体条款。89 次原始 Mind 输出没有一次明确的 accept/reject，不能说执行器吞掉了已作出的同意。某些 Plan 写移动却选了接受求助编号；gateway 依照本人的 speechIntent 保留普通表达，正确地阻止了翻译器替人同意。

现已补齐：本人相关协议的实际提议者、当事人、具体 proposal 字段（排除对方私有关系依据）、提议事件及本人真正接收到的原话。speechReferences 与 current.agreements 一致；全部相关 proposed/active 保留，仅终态保留最近窗口。定向验证包含超过旧窗口数量的待回应协议，确认每个回应引用都能看到对应事项，又不会自动成为本人接受。

`qwen-proposal-context-seed31-20260907` 从 reception 样本第 2 月的三份真实待回应提议续跑至第 3 月。此为保留阴性历史的诊断续跑，不是最终版本从初始状态开始的完整验收；未加入新提议、强制回应或物资。


## 提议上下文诊断续跑结果

`qwen-proposal-context-seed31-20260907` 已完成第 2→3 月，全部 73 次调用仍为 lan-qwen。该月实际形成 35 次新 Mind、2 次保留当前安排、1 次 Plan 续编，无翻译失败，执行 11 个完成动作与 3 个推进动作。只有三人、没有造物或后代；原有三份提议和新增一份 assist 都仍为 proposed。

有来源的行为变化：精卫在请求上下文完整后能够区分柳如是的路线观察需求和尼尔的多个黏土/木材提议，表达先处理前者、后者暂缓；Qwen 也两次实际选 keep-current。这证明新输入和保留安排接口被实际用到，不能证明协作已履行。仍没有明确 accept/reject 或与之匹配的执行承诺，部分动作与表达的语义仍不一致。

下一步的代码审计也定位了开放取物边界：同地人物前两件物品有原生未经授权取物入口与抵抗结算；自由世界动作没有可感知的他人持物引用，因此第三件物品等创造性取物不能走同一流程。项目交付物又在普通transfer里被“等待请求者查收”硬挡，world consume/relocate却绕过该规则。这是社会规范与物理执行不一致，尚未修复，也不能宣称真实模拟已经出现偷窃。

本轮新增的同月认知来源、保持已有安排、提议上下文与动作回执投影，已通过对应定向验证、前后端类型检查及DDD边界检查。完整文明与社会体验验收仍未通过，Goal保持进行中。


## 开放取物与残留回应门槛

本轮完成两项确定的世界边界修复：

- 近身真实可感知的他人持物全部可被引用，包括第三件物品；不展示远处背包或记录内容。World transfer 与原生 transfer 共用数量、空间触及、持有者抵抗和实际后果。取放先作为一件真实事情结算，后续加工收到回执后再规划；失败不会继续加工假想取得的原料。
- 项目交付保留从物理取用禁令改为带来源的社会事实。普通取放、自由消耗、自由搬移都记录真实取用及原交付来源；只有当时实际在场可感知者获得经历，原本不知道请求的人不会从元数据获得隐藏归属信息。没有自动制造道德谴责、关系扣分或回应行为。

继续追踪冻结的错误 Plan 时，还发现 buildDecisionContext 残留更直接的限制：一旦有 requiredSocialResponses，原代码只向模型提供回应选项和紧急休眠，其余物理选项全部被移除。第 8 次诊断请求中，人物要去看水，availableSteps 却只有 6 个接受/拒绝。现已移除这个候选门槛和人工类别排序。提议及其后果仍可见，回应仍独立选择；它不会使其它真实行动消失。定向实际执行证明待回应提议仍存在时人物可以走动或取物，且该行为不会自动接受或拒绝。

`qwen-open-choice-seed31-20260907` 从上一诊断历史第 3 月续至第 4 月：本月 34 次请求，15 次新 Mind、4 次保留安排，没有翻译失败；3 个完成动作、1 个推进，没有造物或出生，4 份提议仍为 proposed。具体身体动作重新进入候选，但 Qwen 仍存在步骤文字与所选入口不一致，不能宣称恢复选项已经解决智能问题。

为区分协议与模型行为，保留了单条冻结请求的对照：去掉 native format、移除 JSON 示例、缩短系统说明、调整字段生成顺序、调整 Schema 分支排列。前三项仍存在错配；字段先选只使说明更贴近所选社交动作，未证明原材料试验意图得到落实；分支排列也未改善。上述临时提示/排列均未接入产品，不能用更顺的说明掩盖原目标没有推进。

新样本 `qwen-open-choice-seed17-20260907` 使用当前版本，从另一代表性初始种子运行两个月；仍只使用 Qwen，无物资/知识注入。该样本结果另行记录。


本轮机制检查：`test-world-transfer.mjs` 覆盖邻格取放、第三件近身持物、追随已见目标的可达位置、抵抗失败、真实数量及超过旧8件上限的转交、后续加工未提前执行、墙体阻断；`test-project-delivery-use.mjs` 覆盖原生/自由两路径的统一归属事实及可见性；`test-cognitive-reception.mjs` 新增真实提议仍待回应时，另一人照常执行物理行动而不自动表态。类型与DDD边界检查通过。这些仅证明机制，不作为自然犯罪、合作或文明已发生的证据。


## 新种子结果与下一处架构断点

`qwen-open-choice-seed17-20260907` 已从当前版本初始状态完成两个月：3 人存活，66 次新 Mind、5 次保留安排，175 次 Qwen 请求；23 个动作，其中只有少量真实位置/物资变化。没有协议、造物或出生；第二月 13 次翻译失败。第一月格式可用没有延续成稳定的目标执行，因此本样本没有通过智能与社会体验验收。

本轮没有将提示词对照的临时改动写回生产，也没有切换 DeepSeek。已实现的改动是开放行动范围、真实取放和来源后果；还不能证明自然偷窃、协作或文明发展已经发生。

只读架构检查给出下一步的明确方向：Plan 的当前一步应是语义操作与实际目标，而非与文字步骤分离的 o1/o2 选择。World 可以编译 typed native operation request，application 复用现有 ActionOption 构造器形成真正的顶层 move/transfer/act/attend/talk/inscribe，再进入原执行器。不可简单把所有高级动作塞进 world-interact effects，否则现有协议、技术、工程与记录等按顶层动作类型运行的后处理会丢失。接受/拒绝等可以直接绑定本人已有 speechIntent 的真实事项；自创提议还需要保存本人实际提出的具体条款，不能继续套用菜单默认内容。

这尚是下一轮要实施并验证的架构工作，不以方案本身表示 Goal 完成。当前完整目标仍未达成。
