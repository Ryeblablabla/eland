# v30 稳定技术请求身份实验

状态：稳定身份机制接受；整体学习链继续修订。

## 决定

v29/v30 的 3×10 年所有引擎与观察指标逐种子完全一致，证明恢复稳定主受众 ID 没有再制造额外历史分叉。请求 `5 / 4 / 0`、重投影 unique project/teacher `9 / 4 / 0`，示范仍为 0，生产 `0 / 1 / 4`。接受稳定身份与多受众审计修正，不升级整体学习候选；下一断点是匹配可靠持有人不在完全同一体素，项目请求无法到达或被观察。

## 单一因果假设

若技术请求的 option/representation 身份仍锚定“项目＋请求者＋排序第一位的尚未询问主受众”，而真实 action audience 可以包含同一时刻的全部未询问同地人物，那么广播不会因为受众数量变化而改写规划器的确定性排序。候选历史应只在实际到达受众和其后回应处产生差异。

这不是把结果写死：主受众仍来自本人当前可见同地人物；其他受众仍必须真实同地；示范、材料、target、response、模仿与可靠化均沿用 v28 守卫。

## 矩阵与门槛

- 定向测试断言有无知识旁观者时 option ID 仍等于 v28 的主受众形式，实际 audience 同时包含旁观者与可靠示范者。
- 使用 v28 direct baseline 的相同 seeds `185 / 20260815 / 20260816`、`3×10y`；v29 只作为失败案例，不升级为基线。
- v28/v30 的第一次请求 option ID 必须可解释为同一稳定语义；全部来源和重复守卫为 0。
- 至少 2 个种子产生请求，生产完成中位数不低于 v28 的 2；出现自然示范才进入 30 年，否则记录“持有人未同地”作为下一断点。
