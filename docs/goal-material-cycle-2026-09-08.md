# 阶段 A：材料循环

新 Goal 的第一个执行批次，2026-09-08 22:44（上海时间）开始，上限 2 小时。

- 主要问题：开放造物已经能够占据网格，但取材、造物组件和回收没有共享实际材料状态。
- 假设：补齐领域循环及直接操作入口后，木材和湿土都能完成取得、排布、承重使用、重排、拆取和再次使用；不需要模型虚构设施功能。
- 交付：沿用现有 Work 聚合和执行器，增加直接装配入口，修复人工体素的回收及组件同步。
- 验证：一条两种材料的定向循环，加相关现有验证与 TypeScript 检查。开发指定输入和操作，不算自主演化成果。
- 模型预算：Qwen 0 次，DeepSeek 0 次，自主社会试验 0 次。未启动观察进程。

开发验证首先发现：原木满体素被 `supportsStanding` 按名称排除，摆成实体后无法踩踏；修正为共享实体材料接触语义后，实际移动和布局变化验证通过。随后复现回收错误：2 份人工木材拆掉一部分，可用材料与 Work 组件合计变成 5 份，且自然采收分支会额外产出纤维。

本批交付已完成，约 26 分钟，未达到 2 小时时间上限。Qwen、DeepSeek、自主社会试验均为 0 次。

实现结果：

- `native assemble` 直接使用本人持有的材料、数量、位置和可选完整布局；已有 Work 可以零新增投入重排。不需要设施名称，也不调用 WorldPlan 重新选择动作。
- 通用近身空间感知显示真实受支撑空位，避免湿土因没有旧建造选项而没有可选位置。
- Work 组件保留材料来源、记录和已有物态；部分拆取、整体拆解、软料取用、World 消耗与替换同步实体布局及剩余材料。移除锚点时保留余件身份，最后实体消失时余料真实散落。
- 连续改造在预检副本上按顺序推演，全部通过后提交，避免中间布局留下无归属材料。
- 原木等实际固体可以承重。自然干燥、浸湿等材料变化同步造物，不将正常转化当作实体丢失。
- 移除领域执行器中与物理数量无关的旧 8 份消耗、8 个对象上限；按实际正整数投入及库存结算。
