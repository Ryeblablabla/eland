# Eland 月度时间与行动执行

本文描述当前代码的时间契约与执行边界，更新于 2026-09-09。它不把规则模式的结果视为模型自主选择，也不证明长期文明演进已经完成。

## 1. 月、活动片段与行动

月是日历和历史提交单位；一年为 12 月。每月包含 15 个可调度的活动片段（activity episode）。事件中的 `planningTick` / `actionTick` 表示片段顺序。

```text
1 月 = 15 个活动片段
健康人物的基础工作量 = 120 work effort / 月 = 8 / 片段
身体经过时间 = 30 个结算日 / 月 = 每片段末分摊 2 日
```

活动片段用于压缩和调度活动，不是一次说话、观察或迈步的自然时长。移动根据地形、路径和身体吞吐量花费工作量，可以在一个片段走过多格，并保留实际路径。当前仍没有分钟级日程和所有短动作共用的细分时间预算。

`elapsedMonths = 0` 是初始状态。执行一个月时固定 `atMonth = elapsedMonths + 1`；月内事实使用这个月号和片段序号。完成 15 个片段与月末处理后，才更新已提交的月数。模型请求的现实耗时不会额外增加游戏月数。

实现：[calendar.ts](../three-body/src/game/eland/domain/calendar.ts)、[action-work.ts](../three-body/src/game/eland/domain/action-work.ts)、[month-execution.ts](../three-body/src/game/eland/application/simulation/month-execution.ts)。

## 2. 明确区分 local 与 model

| 执行模式 | 谁形成新的自愿选择 | 如何推进 |
|---|---|---|
| 显式 `local` | `RulePlanner` | 本地同步规划、执行，不调用人物决策模型 |
| `model` | 配置端点上的人物 Mind | 后台演化也等待真实模型响应，再把已选择的尝试交世界转译与领域执行 |

模型模式通过 `createServerLlmDecider(endpointId)` 设置 `ownsVoluntarySocialChoices`。其本地执行 planner 可以保留已有安排，但不替人物选择新的目标、接受或拒绝社会提议。没有有效模型响应时，能够继续的既有身体工作与领域反射仍可执行；没有既有工作的人可能暂时没有新行动。不能将这种情况解释为人物主动决定发呆，也不能自动换成 `RulePlanner` 为其安排生产或社交。

明确请求模型端点或已选 `model` 模式时，缺少有效端点会报错。当前 `readEvolutionMode` 在配置缺失时默认 `local`，配置未声明模式且没有决策路由时也会选择 `local`；这属于入口的默认模式解析，不是模型请求失败后切换规则。运行结果应按实际 `provider` 区分，不能仅凭“后台演化”名称判断是否调用过模型。

月初认知复核目前仍经过候选筛选和上下文容量安排；月内亲历结果、听见的话、社会行为和编译反馈也能触发复核。新出现的身体需求、损伤或条件恶化以真实事件为来源提供新的审视机会，选择等待不会屏蔽这些变化；普通储备漂移不逐次触发。因此，当前既不是每人每片段固定调用一次模型，也不是“每月最多两次”。同一来源已经交付复核后，不因请求失败就每片段把它当成新经历重放。

实现：[evolution-decision-runtime.ts](../three-body/server/evolution-decision-runtime.ts)、[backend-decider.ts](../three-body/server/backend-decider.ts)、[tick-executor.ts](../three-body/src/game/eland/application/simulation/tick-executor.ts)。

## 3. 人物选择与世界转译

当前新请求采用 Mind 的明确尝试接口：

- `creative`：人物用自然语言选择自己要做的具体身体活动，包括观察、取放和制造；世界编译本次可执行的操作或准备。
- `speak`：人物选择要表达的意思，由言语编译形成忠实原话与言语含义。
- `continue`：保持当前身体工作；当前空闲时保持空闲。
- `wait`：人物选择暂停身体工作并等待。

人物可以独立修改长期目标，也可以独立提供已经选好的原话；形成目标不要求发言。Mind 不填写整套协议接口，言语编译把其选定的意思或冻结原话对应到领域语义；冻结原话的字词、标点和传播强度不会被改写。原话只传播一次，语言与身体操作可以独立成立。请求他人帮忙不会自动产生对方同意、劳动或物资转移。

新身体尝试由 `WorldAttempt` 编译为原生操作、开放物理效果，或具体未编译原因。编译器承接本人的主体、对象与目的，不为人物重新制定长期目标。混合意向中本人要说的话可以转交言语编译，同时保留身体部分。当前新尝试不要求先由 World 写出完整人生计划或完成评分；代码中已有带 `plan` 的 Intent 仍存在按回执续编的路径。

世界返回的是待执行请求。领域层根据当时真实身体、对象、材料和位置执行，才能产生结果。空物理效果不表示目标成功；接口或编译错误也不成为人物已经经历的物理失败。

实现：[agent-prompt-templates.ts](../three-body/server/agent-prompt-templates.ts)、[model-decision-gateway.ts](../three-body/server/model-decision-gateway.ts)。

## 4. 月内执行与短暂摄入

一个月先处理天象、天气、环境变化与月初生命周期，再执行活动片段。每个片段中的人物顺序由种子、分支、月、片段和人物身份确定；后执行者读取前面已经发生的变化。

每个人依次处理既有的休眠与恢复限制、生存和依赖照护反射、必要避护，再执行可继续的原有 Intent 或本模式允许的规划结果。规则反射目前仍负责直接生存危险和照护，这属于当前实现边界；不能把它们算作模型自发形成的选择。

一个人物在片段中共用 `ActivityWorkBudget.remainingEffort`，初始为 8。移动、同一个已选 Intent 的后续步骤及其恢复链共享剩余额度，不为每个原子动作重新发放 8。说话中断结束后可以恢复兼容身体工作；独立声明也不要求为同一句话再排一项身体工作。剩余额度不用于额外选择自愿目标或增加模型回合。

`action-work.ts` 使用游戏归一化劳动量：取放按实际份量和材料质量，加工再结合已有硬度与工具生产倍率；人物既有身体吞吐量决定完成这些劳动需要多少 effort。没有细分劳动量的复杂能力保留原有一片段费用，不能把缺少 `spentWork` 当作免费。它是明确的游戏单位，不是实测工时。材料操作不足额完成时，先用隔离的领域执行预演确认可执行性，再把已投入劳动留在同一 Intent；直接控制的无 Intent 操作保存在人物上。完成前不消耗输入或产出设施。后续接续保留已投入劳动及其事实来源。

移动沿既有路径成本结算，昂贵的单格也累计劳动后才跨越，不能因为是本次调用的第一格而突破剩余额度。未完成单格的劳动保存在人物的 `movementWork`，同一实际起点和下一条边不会因为目标或生存子 Intent 换了身份就丢失；真实转向、位移或路况变化时重新结算。活动片段仍统一分摊经过时间，不能把每次取放、说话或一格移动都单独收取 2 日代谢。

生存反射选中一个具体食物或水源后，将实际来源与完成操作保留在 Intent 的 `target` / `completionAction` 中，目标是实际摄入带来的储备恢复。走到来源附近只是准备：例如去果丛的尝试继续为采集、拿起该次采集真正产生的食物、再摄入。途中正常的少量水分消耗不会把这个未完成尝试改成反向走回水边；新的可见野兽、休眠或照护危险仍通过原有反射处理。

同一片段内，有剩余 effort 时继续这个已选尝试。就手的摄入沿现有即时语义处理，每次必须真正完成、位置不变、人物仍存活且未休眠，水分与营养均未下降并至少一项改善，才能继续下一次摄入。失败、无工作投入或无储备改善会结束执行；有成本的后续操作耗尽预算时，留下真实进度等待后续片段，不使用硬编码动作次数。

生存、照护与避护均清除后，可以继续本人原有、仍有效的身体工作；没有原工作就不在这里形成新目标。物品与地表产物需要通过真实取放进入持物，饮水使用真实可接触的水源或领域支持的储水对象，不增添物资，也不把遥远移动和采集当成免费操作。

可达水源的补水移动仍按实际路径和工作量执行，但不再以“路程可能超过储备剩余时间”为资格门槛，推迟到人物更加虚弱才出发。储备耗尽与立即死亡不是同一事实。

全部人物完成本片段的行动机会后，统一结算经过的 2 日身体代谢，下一片段读取更新后的储备。

## 5. 身体储备与月度生命周期

身体数值采用游戏份量，不作医学模拟。清醒基础消耗由既有摄入份量锚定：

| 量 | 当前含义 |
|---|---|
| 一份普通 Food | 营养 +48、水分 +4；48 营养约对应 7 日基础消耗 |
| 一次饮水 | 水分 +58，约对应 3 日基础消耗 |
| 清醒每日基础消耗 | 水分 `58 / 3`，营养 `48 / 7` |
| 100 储备 | 基础水分约 5.17 日、营养约 14.58 日的短期缓冲 |
| 水分短缺 | 低于 25/10 时，每日健康损伤分别为 2/7 |
| 营养短缺 | 低于 25/10 时，每日健康损伤分别为 2/6 |
| 脱水休眠月成本 | 水分 0.35、营养 0.3、健康 0.25；严重乱纪元额外损伤健康 0.15，均按经过时间分摊 |

跨过短缺阈值时，只累计实际处于该阈值以下的日数。疾病、冷热、妊娠、产后恢复和特质的代谢修饰保留相对比例。附近实际火源仍可减轻寒冷营养负担；休眠中的营养成本仍受其代谢特质影响。

短期储备与短缺损伤由 `body-metabolism.ts` 计算，`advanceBodyTime` 形成片段身体事实。健康耗尽时使用既有死亡入口，记录死亡、遗体、遗物和意图后果，不留下健康为零却仍活动的人物。

年龄按月数派生；疾病、冷热状态、衰老、妊娠、产后恢复和有利条件下的恢复继续在月度生命周期处理。休眠复水阶段按既有月初逻辑检查实际储备及恢复来源，不自动补水补粮。月末 `advanceBodies` 不重复扣除短期储备、短缺伤害或休眠成本。

实现：[body-metabolism.ts](../three-body/src/game/eland/domain/body-metabolism.ts)、[monthly-processes.ts](../three-body/src/game/eland/domain/monthly-processes.ts)。

## 6. 长期工作与真实结果

Intent 保留实际目标、当前步骤、进度和来源，可以跨片段、跨月推进。等待、复核期限和执行失败是不同状态；期限经过本身不证明行动失败。新发言不会当然清空已有身体工作。

每一步的回执区分操作是否发生、目标是否推进、证据是否改变。观察可以完成，而长期问题仍未解决；一次准备移动只能证明位置变化，不能证明已经取材、加工或取得他人帮助。当前人物选择的操作需要实际执行回执，不能仅因准备条件已经成立就静默宣布完成。

创造依靠真实材料、数量、位置与实体变化。构件投入、取放、加工、拆解和回收保留对应来源；同一造物的改造继续使用原实体身份。材料排列或设施名称本身不证明生活功能，实际使用、加工结果及对身体或生产的影响才是用途证据。该原则不意味着当前领域已经覆盖全部设施与技术。

新尝试完成或遇到实际障碍后，可以将当前结果交回 Mind；世界转译不因此取得人物下一阶段目标的决定权。

实现：[intent-execution.ts](../three-body/src/game/eland/application/simulation/intent-execution.ts)、[intent.ts](../three-body/src/game/eland/domain/intent.ts)、[works.ts](../three-body/src/game/eland/domain/works.ts)。

## 7. 提交、回放与当前限制

月末完成生命周期处理，整理本月事件顺序，更新 `elapsedMonths` 并追加历史，再形成玩家观察投影。模型长程运行等待当前月完成后逐月保存；读取已有回放不重新调用人物模型。话语、模型提案、实际操作和身体变化在记录中各有来源，投影不能补写尚未发生的事实。

有限化身使用同一月执行器的隔离工作状态：查看环境不推进片段，提交行动或等待会让当前月份的参与者推进一个片段。模型模式下，非玩家人物使用与普通演化共享的月内模型规划入口；被玩家控制的人暂时排除，解除控制后恢复独立模型机会。已采纳的模型响应随隔离状态冻结，恢复与回放重用这些响应，不重复发送网络请求。显式 local 模式仍使用本地规划器。

当前时间模型还有明确限制：

- 当前按归一化工作量组织片段内连续步骤；观察和未细分的复杂能力仍保留一片段费用，尚无完整的分钟级日程与所有动作的真实时长模型。
- 地形移动、月初环境过程和月末疾病/生育采用不同的游戏抽象；不能从“30 个结算日”推断所有世界过程已经实现逐日变化。
- 模型模式仍有认知候选筛选和上下文容量；请求失败时可能缺少新的自愿行动，尚不能宣称所有人物始终行动充分。
- 局部时间验证或回放成功，不证明持续生产、独立社会选择、多代繁衍和跨文明演进已经成立；这些需要最终版本的连续真实运行证据。

实现：[month-boundary.ts](../three-body/src/game/eland/application/simulation/month-boundary.ts)、[run-evolution-executor.ts](../three-body/server/run-evolution-executor.ts)、[player-embodiment-month.ts](../three-body/src/game/eland/application/player-embodiment-month.ts)。
