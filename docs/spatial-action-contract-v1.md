# ELAND 空间行动契约 v1

状态：当前感知、规划、空间执行和动作事实契约。已经移除的 `PerceptionBundle / Affordance / PlanDecision / monthlyBudget / WorldDeltaRef` 伪接口不再保留。

前置：[规则优先人物架构](./rule-first-agent-architecture-v1.md) · [体素世界](./pixel-world-v1.md) · [月度时间模型](./monthly-time-model-v1.md)

代码入口：`application/simulation/month-execution.ts`、`application/action-options.ts`、`application/player-embodiment.ts`、`application/rule-planner.ts`、`domain/action.ts`、`domain/action-executor.ts`、`domain/model.ts`。

## 1. 目标

人物从身体、环境、关系、记忆、承诺和局部不确定性形成需要；应用层把本人可感知的事实编译成合法候选；领域层把持续意图落实为受体素、距离、材料、身体和授权约束的原子行动。

```text
当前权威状态
→ 固定本月 atMonth
→ 15 个规划刻度
→ 当前人物重验活动 Intent；需要复核或重规划时才重建上下文和合法候选
→ 创建、继续、修复、挂起或结束 Intent
→ 提交一个 PrimitiveAction
→ 新事实立即进入本月后续人物和后续刻度
```

一个规划刻度不是一个月，也不是一次长期任务。移动始终沿连续相邻边执行：普通人物受本刻地形成本预算约束，低成本道路可在一刻内连续跨两条边；有限化身的一次移动命令只允许跨一条合法相邻边。建造、耕作、搬运、学习、照护和协商可以延续多个刻度、月份或项目阶段。

## 2. 顺序与时间

每个已提交月份固定执行 15 个 planning tick：

1. 月初固定 `atMonth = elapsedMonths + 1`，推进气候、天气、生态、休眠阶段、协议生命周期和记忆维护。
2. 每个 tick 依据 `seed + branchId + atMonth + tick + personId` 形成稳定人物顺序。
3. 当前人物先读取最新权威状态并处理紧急生存、依赖照护和住所维持等中断；稳定活动意图若无需复核且没有新机会，不重建完整候选集。
4. 需要复核或重规划时，本地规划器才重建局部上下文和合法候选并创建或修复意图；否则只重新校验并推进当前意图的下一原子动作。
5. 动作立刻修改权威状态并写入事件；同 tick 中排序更后的人物可以读到该结果。
6. 15 个 tick 完成后结算身体、关系、项目、共同体、观察投影和文明终局。

因此不存在“所有人物先按月初快照统一计划，再统一执行”的阶段。确定性来自固定月份、稳定排序和本地规则，而不是隔离同月变化。

## 3. 认知与决策边界

正式本地规划器可以：

- 在当前合法 `ActionOption` 中排序；
- 创建、继续、修改、挂起、恢复或结束 `Intent`；
- 保存稳定目标、项目、协议、来源事实和本地理由；
- 在失败、目标消失或新证据出现时重新规划。

它不能：

- 读取人物不可见且没有来源记忆的目标；
- 把文明指数、时代阶段、里程碑或能力地图当作奖励；
- 用隐藏配方、他人背包、全局地图或未来事实生成候选；
- 在决定中声明尚未发生的建造、取得、治愈、学习或制度结果。

当前 `DecisionContext` 包含当前人物、可见格、可见人物、可见掉落物、可见动物、合法候选、后续候选和活动意图。实现内部仍持有完整 `SimulationState` 供规则函数查询，这是需要继续收紧的类型边界；任何新 planner 或 decider 仍必须只使用人物可感知字段及显式合法候选。

实时模型只接收服务端整理的局部 DTO，并且只能在本地已经生成的合法候选中重选。模型输出不能直接提交路径、原子动作或客观后果；选择在当前上下文和动作执行边界都要重新校验。模型缺席或失败时使用预先计算的本地决定。

## 4. 候选、意图和项目

`ActionOption` 是当下可执行方向，保存目标谓词、下一动作、目标引用、预计时长、来源事实，以及可选的项目、关系或记录使用 basis。option ID 是当月审计标识，不是跨月领域语义。

`Intent` 是持续执行状态，至少保存：

- 稳定目标和下一 `PrimitiveAction`；
- `active / suspended / completed / blocked / abandoned / failed` 状态；
- 创建、最近进展和计划期限月份；
- 来源 DecisionFact、项目、协议与关系 basis；
- 动作事件、阻塞原因和重规划次数；
- 被生存、照护、履约或复盘中断时的父子返回关系。

项目保存跨人物、跨月工作所需的材料缺口、固定场地、贡献者、尝试、失败、证据和完成条件。意图可以执行项目的一步，但项目名本身不能制造物质或宣告完成。

未知资源搜索必须来自有来源的局部候选区域，并保存已经尝试的位置和计划 basis。新 project ID、月份流逝或更高紧迫度不能清空同一人物的失败搜索记忆。

## 5. 原子动作

当前只有五类 `PrimitiveAction`：

| 类型 | 当前语义 |
| --- | --- |
| `move` | 沿确定性可站立路径前进；普通执行受本刻地形成本预算约束，有限化身命令只取一条相邻边 |
| `transfer` | 在人物、地面和容器之间移动精确物质数量 |
| `act` | 执行物质作用、生殖、捕猎或休眠出入等领域操作 |
| `attend` | 观察、阅读或验证一个真实目标 |
| `talk` | 用口头、手势或实体记录提交有来源的表达 |

每次执行都重新检查：

- 人物是否存活、清醒且允许执行该动作；
- 目标是否仍存在且位于动作允许的距离；
- 路径、站立高度和目标体素是否有效；
- 材料、工具、数量、容器、权限或协议引用是否准确；
- 项目、记录、技术和关系 basis 是否仍与当前事实匹配。

无法满足时必须产生 `blocked` 或 `failed` 事实；不能静默换目标、借用隐藏物资或把人物解释改成成功。

## 6. 移动与空间连续性

- 寻路使用当前 `VoxelWorld` 上的确定性四向站立路径。
- 普通人物每个动作 tick 从完整路径取当前地形成本预算允许的连续段；低成本道路可包含两条边，高成本地形至少允许一条边，但不能瞬移到目标。
- 无路、拘束或休眠时移动被阻塞。
- 每次真实移动更新 `cellId / z`、身体消耗、`pathSegment` 和通行计数。
- 反复通行可使草地变为土、再变为压实土；计划路径本身不构成道路。
- 未满一岁的同处、清醒亲生婴儿可以随亲代真实移动；休眠者和更大儿童不会被隐式搬运。

路径缓存只优化计算，体素发生变化后必须失效；缓存不是世界事实。

### 6.1 有限化身的空间命令

- 第一人称转头、瞄准、查看近旁人物 / 结构和展开操作提示是只读观察，不推进刻度。
- 移动候选只从人物当前站位的四向邻格中投影；邻格必须存在长度恰为一条边的可站立路径。WASD 或场景点击选择的是这个候选，不是客户端直接写入坐标。
- 客户端只提交候选的稳定 `optionId + choiceKey`。服务端在该人物的稳定顺序轮次重新生成局部候选；前序人物造成的占用、物质或路径变化会使命令被拒绝或由领域动作记录阻塞，不能沿用过期前端预览强制成功。
- 被控制人物仍先经过休眠、恢复、生存反射、依赖照护、幼儿限制和必要避护；这些规则接管时，玩家移动或操作不会覆盖它们，但同一世界 tick 中其他人物仍完整行动。
- 建造按钮只展示当前真实 `DecisionContext` 已有的建造 / 项目候选。选择后仍由同一 Intent / Project 步骤、`PrimitiveAction`、材料 / 工具 / 场址 / 权限校验和 ActionFact 后果执行；有限化身不拥有独立蓝图、无限材料或直接放置体素的权限。

## 7. 交互和结构

| 行动 | 空间要求 |
| --- | --- |
| 取放、摄入、点火、加工、阅读实体载体 | 与精确 holder 或目标处于动作允许范围，通常同格 |
| 照护、交换、亲密行动和普通近身沟通 | 双方执行时仍真实同处；预言、手势技术/材料请求和设施协调等结构化沟通按动作定义的明确半径校验 |
| 挖掘、分离、放置体素 | 同格或正交相邻，由具体 action validator 决定 |
| 进入、休息和恢复 | 人物真实位于可达内部格 |
| 观察 | 由当前可见范围、地形和身体状态决定 |

结构由已放置体素的支撑、顶部覆盖、侧向围护、入口和可站立空间重算。不存在独立 `ComponentKind` 权威构件清单；项目或人物声称“造好住所”不会直接产生防护。

地面劳动同样修改真实物质或实体：采集产生掉落物，挖掘改变物质柱，灌溉需要真实水体连通和坡降，耕作读取种子、土壤、水分和生长阶段。

## 8. 同刻度冲突

人物按本 tick 的稳定顺序直接提交：

- 两人取得同一耗尽物质时，先提交者成功，后提交者读取新状态后阻塞或重规划。
- 两人向同一体素放置互斥材料时，第一项成功，第二项重新校验失败。
- 需要近身的双人行动在执行时重新确认双方同处、存活、清醒和授权；允许明确半径的结构化沟通则重新校验双方距离与对应来源。
- 当月新发生的死亡、休眠、伤害、资源耗尽或路径封锁会影响后续动作。

冲突结果必须进入事件和人物可获得的后续事实，不能为保证原计划完成而回滚先提交的合法结果。

## 9. 动作事实

每个实际动作提交一条当前 `ActionFact`：

```ts
interface ActionFact extends BaseEvent {
  kind: 'action'
  actionTick: number
  who: PersonId
  intentId?: string
  cause: 'intent' | 'survival-reflex' | 'player-embodiment'
  action: PrimitiveAction
  fromCellId: number
  toCellId: number
  fromZ: number
  toZ: number
  pathSegment: number[]
  status: 'progressed' | 'completed' | 'blocked' | 'failed'
  result: string
  diff: Record<string, unknown>
}
```

`BaseEvent` 另保存 `id / atMonth / orderInMonth / planningTick / orderInTick / cellId`。月末会按 planning tick 和 tick 内顺序规范化事件排序。

`diff` 保存该动作已经发生的结构化后果；它不是另一个可独立应用的 `WorldDelta` 类型。权威恢复读取持久化的 `SimulationState` checkpoint/delta，历史解释读取 `WorldEvent`。

## 10. 验收不变量

- 每个完整月份恰有 15 个规划刻度。
- 后续人物能看到同 tick 先提交人物造成的新事实。
- 决策器不能合法引用不可见且无来源记忆的目标。
- 人物不能在未到达时作用于远处对象。
- 普通移动不超过本刻地形成本预算；有限化身的一次移动命令恰好只选择一条合法相邻边，二者都保存实际路径和高度。
- 没有新决定时，活动意图仍可继续推进。
- 失败和阻塞留下真实位置、动作、原因与结构化差异。
- 每个结构效果都能从物质体素与使用事实重算。
- 模型失败不阻止本地规则提交月份。
- 同一种子、分支和已提交历史得到相同的执行顺序与后果。
